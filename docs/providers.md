# LiDAR providers and coverage

This page is the user-facing catalogue of the LiDAR and elevation sources
currently integrated into lidar2map. It records the provider code to select,
nominal resolution, native coordinate system, coverage, credentials, and
source-specific constraints.

For sources that were evaluated but not integrated, and for the technical
history behind provider decisions, see the
[provider roadmap](lidar_providers_roadmap.md). To add a source, see
[Contributing a LiDAR provider](contributing-providers.md).

## Select a provider

- In the GUI, use the provider dropdown at the top of the LiDAR form.
- In every LiDAR CLI command, pass `--provider <code>` explicitly.
- `LIDAR2MAP_PROVIDER` does not replace the required CLI argument.

Use `fr-ign` for mainland France. Codes ending in `-laz` in the table are
internal point-cloud twins: normally select their parent provider and enable
**DFM mode** in the GUI, or pass `--laz` in the CLI.

## Accounts and API keys

Most providers need no account. The exceptions currently exposed to users are:

| Provider | Credential | How to supply it | Notes |
|---|---|---|---|
| `se-lantmateriet` | Free GeoTorget account | `LANTMATERIET_USER` and `LANTMATERIET_PASS` | The STAC catalogue is public; credentials protect the download host. |
| `fi-maanmittauslaitos` | Free National Land Survey API key | `--api-key <key>` or `NLS_FINLAND_API_KEY` | Required for WCS downloads. |
| `dk-datafordeler` and its LAZ mode | Free Datafordeler API key | `--api-key <key>` or `DATAFORDELER_API_KEY` | The same key is used for the raster DTM and point cloud. |
| `pt-dgt` | Free DGT account | `DGT_USER` and `DGT_PASS` | Username/password authentication; this is not an API-key parameter. |
| `us-3dep` | Free OpenTopography API key | `--api-key <key>` or `OPENTOPOGRAPHY_API_KEY` | For public 1 m data without an account, prefer `us-tnm`. `OPENTOPOGRAPHY_DATASET` selects the OpenTopography dataset; `USGS1m` requests the 1 m product, while the provider fallback is `USGS10m`. |

The `us-3dep` LAZ/DFM path uses the public Planetary Computer point cloud and
does not require an OpenTopography account.

## Coverage

![lidar2map LiDAR coverage map](../coverage.png)

The colour map summarizes available national and regional coverage. Its
interactive GeoJSON displays each zone's `NAME` and provider code when clicked:

🗺️ **[Open the interactive coverage map](../coverage.geojson)**. GitHub renders
it directly; it can also be dropped into [geojson.io](https://geojson.io) or
QGIS to test a point.

The map is regenerated by `coverage_map.py` from zone titles in
`providers/*.py`, so the map and GUI use the same source.

### USA and Canada

**🇺🇸 USA and 🇨🇦 Canada are supported and working, but are not drawn as
full-country polygons.** `us-tnm` / `us-3dep` (3DEP) and `ca-nrcan` (HRDEM)
have project- or population-based coverage rather than wall-to-wall national
coverage. Drawing the whole country would overstate availability.

Check a US area with the
[TNM Downloader](https://apps.nationalmap.gov/downloader/). USGS 1 m source
tiles are 10 × 10 km COGs, but lidar2map reads only the requested bounding-box
window through `/vsicurl/`; it does not download each complete source tile.

## Evaluated and future sources

The [provider roadmap](lidar_providers_roadmap.md) records every evaluated
source, including sources left out because they lack a programmable endpoint,
serve only rendered imagery, have inadequate coverage/resolution, or impose an
incompatible licence. It also records candidates worth rechecking.

To propose or implement a source, follow
[Contributing a LiDAR provider](contributing-providers.md).
